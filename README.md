# 커리어 나침반 · 시제품

취업·이직 고민을 먼저 적고 양력 생년월일, 희망 직무, 현재 상태, 입사 목표일을 입력하면 3단계 행동 계획을 보여주는 웹 시제품입니다. 출생시간은 받지 않습니다.

생년월일은 연도를 바로 적고 월·일을 고릅니다. 입사 목표일은 3·6·12개월 뒤 버튼으로 빠르게 정하거나 원하는 날짜를 직접 선택할 수 있습니다.

## 실행

```sh
npm ci
npm run dev
```

실행 후 터미널에 표시된 주소를 브라우저에서 엽니다.

Gemini 인증값이 없어도 기본 행동 계획을 확인할 수 있습니다. 고민에 맞춘 커리어 인사이트와 AI 계획을 사용하려면 Google AI Studio에서 발급한 비밀 인증값을 프로젝트의 `.env.local` 파일에 `GEMINI_API_KEY=발급받은값` 형식으로 저장하고 개발 서버를 다시 시작합니다. 이 파일은 Git에 포함되지 않습니다. 인증값을 설정한 경우 고민·희망 직무·현재 상태·입사 목표일과 생년월일에서 계산한 참고 지표가 Google AI로 전송됩니다. 생년월일 원문은 전송하지 않습니다. AI 해석은 자기 성찰을 위한 참고 의견이며 합격이나 적성을 확정하지 않습니다.

Google 로그인은 선택 사항입니다. 로그인하면 새로 생성된 AI 커리어 인사이트의 요약·강점·점검할 점·질문을 Supabase 데이터베이스에 자동 저장하고 최근 10개를 다시 볼 수 있습니다. 로그인하지 않아도 인사이트와 행동 계획을 사용할 수 있습니다. 생년월일, 고민 원문, 행동 계획과 채용 공고는 저장하지 않습니다. Supabase 연결에는 `.env` 또는 `.env.local`의 `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 사용합니다. 이 공개용 키와 별도로, 데이터베이스는 로그인한 본인만 자신의 해석을 읽고 추가하도록 접근 규칙을 적용합니다.

새 Supabase 프로젝트에서 실행한다면 `supabase/migrations/202609230001_create_saju_readings.sql`을 SQL Editor에서 적용하고, Google 로그인 제공자 및 앱 주소의 허용 복귀 주소를 설정해야 합니다. 현재 연결된 실습 프로젝트에는 이 설정을 적용했습니다. 다른 주소에 배포할 때는 그 주소도 Supabase 로그인 허용 목록에 추가하세요.

현재 화면은 자동 공고 목록을 제공하지 않습니다. 인사이트는 한자 없이 잠재력과 취업·이직에 활용할 행동을 중심으로 보여주며, 저장된 이전 내용도 화면에서는 한자를 정리해 표시합니다. 결과 마지막 이미지에는 `내일의 나는 오늘의 내가 만듭니다`와 고민에 맞는 출처 있는 영문 명언·격언을 보여줍니다. 화면 상단에서 한국어와 영어를 바꿀 수 있으며, 이전에 저장한 내용은 생성 당시 언어로 남습니다.

첫 화면의 쿼카는 마우스를 올리거나 눌렀을 때 웃으며 반응합니다. 터치와 키보드로도 인사할 수 있고, 기기에서 움직임 줄이기를 선택한 경우에는 흔들림 없이 표정만 바뀝니다.

MY INSIGHTS에서는 저장된 기록을 선택하고 쿼카의 `처음부터 듣기`를 누르면 음성과 타이핑 자막을 함께 볼 수 있습니다. 쿼카가 말하는 표정으로 움직이며, 중단·다시 듣기·전체 원문 읽기를 제공합니다. 기기 음성이 지원되지 않으면 선택한 인사이트를 Google AI에 보내 음성을 생성합니다. 이때 기존 서버의 `GEMINI_API_KEY`를 사용하며 음성 파일은 데이터베이스에 저장하지 않습니다.

## 주요 문서

- `docs/PRD.md`: 무엇을 왜 만들지 기록합니다.
- `docs/specs/`: 기능이 어떻게 동작해야 하는지 기록합니다.
- `docs/status.md`: 현재 어디까지 진행됐는지 기록합니다.
- `AGENTS.md`: Agent가 작업할 때 따르는 기본 원칙입니다.
- `tests/`: 자동화된 검증을 관리합니다.

## 폴더 구조

```text
├── app/                 화면과 페이지
├── lib/saju/            생년월일 기반 참고 지표 계산
├── docs/
│   ├── PRD.md           제품 목표와 범위
│   ├── status.md        Spec별 진행 상태
│   └── specs/           기능별 요구사항
├── tests/               자동 Test
├── .agents/skills/      반복 작업 Skill
└── AGENTS.md            Agent 작업 원칙
```

이 프로젝트의 AGENTS.md, PRD, Specs, Tests, Status, Skill과 작업 환경을 조합해 Agent가 안정적으로 작업할 수 있는 Harness를 만들어갑니다.

## 작업 흐름

1. 서비스를 실행하고 현재 기능을 직접 확인합니다.
2. Agent와 대화하며 `docs/PRD.md`에 대상 사용자, 해결할 문제와 제품 범위를 작성합니다.
3. 구현할 기능 하나를 정하고 `docs/specs/001-feature-name.md` 형식으로 Spec을 작성합니다.
4. `docs/status.md`에 해당 Spec을 `- [ ]`로 추가합니다.
5. Spec을 기준으로 구현하고 Test와 실제 화면에서 결과를 확인합니다.
6. 구현과 검증이 모두 끝나면 `docs/status.md`의 항목을 `- [x]`로 변경합니다.
7. 다음 기능도 같은 과정을 반복한 뒤 Vercel에 배포하고 배포 주소에서 다시 확인합니다.

한 번에 여러 기능을 구현하지 말고 Spec 하나씩 완료하세요.
