# 004 · 사주 해석 결과 저장

## 목적

로그인한 사용자가 새로 생성한 사주 해석을 나중에 다시 볼 수 있도록 Supabase 데이터베이스에 저장한다.

## 범위와 데이터

1. Gemini가 정상적으로 생성한 해석의 요약, 강점 2개, 점검할 점 2개, 질문과 생성 시각을 저장한다. 생년월일·고민 원문·행동 계획·채용 공고는 저장하지 않는다.
2. 로그인 상태에서 해석을 생성하면 자동 저장하고 성공·실패를 분명하게 알린다. 비회원이나 AI 해석 실패 시에는 저장하지 않는다.
3. 로그인한 사용자는 최근 저장한 해석 10개를 화면에서 다시 읽을 수 있다. 로그아웃하면 목록을 숨긴다.
4. 데이터베이스의 행 수준 보안(RLS)으로 본인의 기록만 읽고 만들 수 있다. 브라우저에는 publishable key만 사용하며, 사용자 ID만 믿어 접근을 허용하지 않는다.
5. 저장에 실패해도 방금 생성한 해석과 계획은 화면에 남는다.

## 데이터 변경과 되돌리기

- 새 `public.saju_readings` 테이블과 본인 조회·추가 정책을 만드는 추가형 migration을 작성한다. 기존 테이블은 변경하지 않는다.
- 장애 시 앱의 저장 UI와 해당 접근 정책을 되돌릴 수 있다. 데이터가 들어간 테이블 삭제는 자동으로 하지 않는다.

## 완료 조건과 검증

- migration 적용 후 테이블과 RLS 정책이 존재한다.
- 비회원의 읽기·추가가 거부되고, 인증된 다른 사용자의 행은 보이지 않는다.
- 저장 후 목록에 나타나며, 로그아웃하면 화면에서 사라진다.
- 타입 검사·테스트·빌드와 실제 브라우저의 비회원 흐름을 확인한다. 실제 Google 계정과 저장 성공 화면은 참가자 로그인 후 검증한다.

## 검증 기록 · 2026-09-23

- 연결된 Supabase 프로젝트에 테이블을 적용했고, RLS 활성화 및 본인 조회·추가 정책 2개를 SQL 조회로 확인했다.
- 익명 REST 조회와 추가는 모두 HTTP 401 `permission denied for table saju_readings`로 거부됐다.
- 실제 비회원 화면에서 AI 해석은 표시되지만 저장되지 않았다는 안내를 확인했다. `npm run check` 26/26과 빌드도 통과했다.
- 실제 로그인 계정의 저장 성공, 목록 재조회, 다른 계정 기록 차단은 참가자 로그인 전까지 미검증이다.
